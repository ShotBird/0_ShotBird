[병렬 구현 규칙 — 같은 작업 트리에서 다른 세션 여러 개가 동시에 구현 중이다 (orchestra)]
1) 먼저 이슈를 claim(gh issue edit N --add-assignee @me). 이슈 본문과 결정(resolution comment)이 정본 — 결정 밖 변경 금지, 결정 밖·미정의 항목이 나오면 멈추고 사용자에게 묻는다.
2) 리포 CLAUDE.md의 테스트·빌드·수칙을 완료 조건으로 따른다. 다른 세션의 미완성 변경 때문에 테스트가 깨지면 원인 파일이 자기 것인지 먼저 확인하고, 남의 것이면 그 사실을 보고한다(남의 파일 수정 금지).
3) git: git add는 자기가 바꾼 파일만(git add -A·git stash·git checkout -- 금지 — 다른 세션 작업을 망가뜨린다). 커밋 메시지에 이슈 번호. pull --rebase 대신 git fetch 후 push, 거절되면 멈추고 보고.
4) 끝나면 커밋 해시와 검증 수치를 resolution comment로 남기고 close. 지도 이슈 본문 편집 금지 — comment 끝에 "Decisions 요지: <한 줄>". 메인 세션에 넘길 일은 "메인 세션:"으로 시작하는 줄로.
5) 브라우저 사용 금지 — 아래 추가 지시에 허용이 적힌 경우만 예외. 브라우저 확인이 필요하면 "남은 브라우저 확인"으로 적고 close는 보류.
